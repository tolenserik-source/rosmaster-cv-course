# Пример отчёта по уроку 9.1 — первое изображение

Это образец оформления на комплектной учебной сцене. Числа проверены запуском на ROSMASTER; имя студента условное. Собственную фотографию и прогнозы до измерений студент добавляет сам. Копия этого примера без собственных данных не является выполненным заданием.

**ФИО:** Иванов Иван — пример  
**Группа:** заполнить  
**Дата выполнения студентом:** заполнить  
**Тема:** размеры изображения, координаты, BGR и оттенки серого.

## 1. Цель своими словами

Открыть изображение программой на Jetson, измерить цвет выбранных пикселей и получить серую версию. Проверить, что порядок каналов BGR отличается от привычного RGB, а после перехода к серому часть цветовой информации теряется.

## 2. Окружение и исходные данные

- Компьютер: ROSMASTER с Jetson, обычная система Ubuntu 22.04; программа запущена через SSH.
- Папка курса: `/home/jetson/rosmaster-cv-course`.
- Python: `3.10.12`; OpenCV: `4.10.0`; NumPy: `1.23.5` — значения проверочного запуска 23.10.2026. В своём отчёте укажите вывод своей проверки версий.
- Исходный файл: `data/scene.png`, **синтетическая учебная сцена**, 800 × 600 пикселей, 3 канала, `uint8`.
- Собственная фотография: `student_photos/ivanov/table.jpg` — студент добавляет сам и записывает её реальные размеры и содержание. Это отдельный опыт, его результаты нельзя брать из таблицы учебной сцены.
- Камера и ROS для этого задания не требуются.

## 3. Точные команды

Подключение из терминала ноутбука:

```bash
ssh jetson@192.168.1.185
```

Команды в терминале робота; `ivanov` заменяется на личную папку:

```bash
cd /home/jetson/rosmaster-cv-course
python3 -c "import sys, cv2, numpy; print('Python:', sys.version.split()[0]); print('OpenCV:', cv2.__version__); print('NumPy:', numpy.__version__)"
python3 -m rosmaster_cv.lesson01_intro --input data/scene.png --out outputs/ivanov/01/baseline
python3 -m rosmaster_cv.lesson01_intro --input data/scene.png --pixel 160 200 --out outputs/ivanov/01/red
python3 -m rosmaster_cv.lesson01_intro --input data/scene.png --pixel 650 420 --out outputs/ivanov/01/blue
python3 -m rosmaster_cv.lesson01_intro --input data/scene.png --pixel 650 200 --out outputs/ivanov/01/green
python3 -m rosmaster_cv.lesson01_intro --input data/scene.png --pixel 445 410 --out outputs/ivanov/01/light
python3 -m rosmaster_cv.lesson01_intro --input data/scene.png --pixel 81 81 --out outputs/ivanov/01/dark
```

После загрузки своей фотографии по инструкции урока:

```bash
python3 -m rosmaster_cv.lesson01_intro --input student_photos/ivanov/table.jpg --out outputs/ivanov/01/own
```

Перенос результатов из локального терминала, открытого в своей папке на ноутбуке:

```bash
scp -r jetson@192.168.1.185:/home/jetson/rosmaster-cv-course/outputs/ivanov/01 .
```

В отчёте студента должны остаться именно выполненные им команды и выбранные координаты. Пароль в команды и отчёт не включают.

## 4. Результаты

В каждом опыте программа сохраняет пять PNG и один JSON. Размер исходной сцены сохранился: `width = 800`, `height = 600`, `channels = 3`. В цветном массиве 600 строк, 800 столбцов и 3 канала; серое изображение содержит одно значение на пиксель.

| Опыт | Координаты x, y | B, G, R | Серое значение | Наблюдение |
|---|---|---|---|---|
| Центр | 400, 300 | 64, 59, 54 | 58 | Точка попала на линию сетки, а не на цветную фигуру |
| Красный круг | 160, 200 | 31, 44, 225 | 97 | Наибольшее значение у R, третьего канала |
| Синий прямоугольник | 650, 420 | 225, 96, 31 | 91 | Наибольшее значение у B, первого канала |

Исходный вид сцены сохранён в `baseline/original.png`, результат преобразования — в `baseline/grayscale.png`. В `red/channel_red.png` красный круг светлый: яркость файла показывает величину R. В `blue/channel_blue.png` светлым оказывается синий прямоугольник. Эти изображения каналов сами по себе серые.

Студент сохраняет `REPORT.md` рядом с папками опытов. Пример комплекта сдачи:

```text
01/

  baseline/  — пять PNG и report.json
  red/       — пять PNG и report.json
  blue/      — пять PNG и report.json
  green/     — пять PNG и report.json
  light/     — пять PNG и report.json
  dark/      — пять PNG и report.json
  own/       — пять PNG и report.json для собственной фотографии
```

Чтобы показать изображения прямо в своём Markdown-отчёте, вставьте такие строки в `01/REPORT.md`:

```markdown

![Та же сцена в оттенках серого](baseline/grayscale.png)
![Моя фотография стола](own/original.png)

```

**Собственная фотография — заполнить после запуска:** размер ___ × ___; центральный пиксель `(x, y) = ___`; BGR = ___; серое значение = ___. В центре изображено ___. После преобразования ___ стало трудно различать по цвету, но сохранились ___. Приложить свои `own/original.png`, `own/grayscale.png`, `own/report.json`.

## 5. Эксперимент: три дополнительных измерения

Прогнозы ниже иллюстрируют оформление. В своём опыте запишите прогноз **до** чтения JSON, выберите точки самостоятельно и объясните расхождения.

| Точка | Пример прогноза до запуска | Измерение BGR / серое | Объяснение |
|---|---|---|---|
| Зелёный объект, 650, 200 | G наибольший; яркость около 150 | `[31, 225, 31]` / `145` | Большое G даёт светлый участок в зелёном канале |
| Светлая шкала, 445, 410 | Каналы равны; яркость около 240 | `[240, 240, 240]` / `240` | Светло-серый участок: высокий R есть, но объект не красный |
| Тёмный фон, 81, 81 | Все каналы малы; яркость около 50 | `[54, 49, 44]` / `48` | Фон тёмный; немного больше синего канала |

Менялся только параметр `--pixel`; исходное изображение оставалось тем же. Отдельные папки `--out` позволили сохранить результаты всех измерений. Серое значение зависит от трёх каналов с разными весами, поэтому не равно их простому среднему.

## 6. Ответы на вопросы урока

1. В `image[200, 160]` первый индекс выбирает строку `y = 200`, второй — столбец `x = 160`. Поэтому на изображении это точка `(160, 200)`.
2. Три значения BGR описывают интенсивности синего, зелёного и красного каналов. Одно серое значение передаёт яркость, но не хранит три составляющие отдельно.
3. Однозначно восстановить исходные цвета нельзя: разные сочетания BGR могут дать одно и то же серое значение.

## 7. Проверенный отрицательный пример

Для учебной сцены проверена команда с координатой за правым краем:

```bash
python3 -m rosmaster_cv.lesson01_intro --input data/scene.png --pixel 800 200 --out outputs/ivanov/01/invalid
```

Программа сообщает: `Пиксель (800, 200) вне изображения 800x600; допустимы x=0..799, y=0..599.` Причина — нумерация с нуля. Для измерения красного круга использована допустимая точка `(160, 200)`; повторный запуск сохранён в `red/`. Папка `invalid/` для отчёта не требуется: ошибочный запуск не сохраняет изображения.
