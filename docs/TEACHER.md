# Самостоятельное прохождение: подготовка и самопроверка

[Оглавление](../README.md) · [Настройка стенда](SETUP_ROBOT.md) · [Решение проблем](TROUBLESHOOTING.md)

Цель курса — чтобы студент самостоятельно получил изображение, объяснил преобразование, провёл небольшой эксперимент и перенёс освоенный алгоритм на данные ROSMASTER. Каждая тема заканчивается наблюдаемым результатом и коротким отчётом. Пройдите настройку сами по [командам для нашего стенда](SETUP_ROBOT.md), затем выполняйте темы последовательно. Каждый неизвестный параметр сначала найдите командой, проверьте наблюдением и запишите в паспорт.

## 1. Подготовьте стенд один раз

Заполните [паспорт ROSMASTER](../templates/ROBOT_PASSPORT.md). Впишите фактическую плату, образ ОС, ROS-дистрибутив, интерпретатор, рабочую папку, способ входа в контейнер при его наличии, модель камеры и LiDAR. Зафиксируйте один проверенный маршрут запуска камеры, реальные топики и их типы, разрешение RGB, кодировку/единицы depth и источник калибровки. Используйте свою действующую учётную запись; пароль и SSH-ключи не включайте в публичные материалы.

Запустите `python3 tools/doctor.py` и выполните базовый урок 9.1 в той среде, которую будете использовать. На ROS-стенде отдельно проверьте импорт Python 3 `rospy`/`cv_bridge`. Если используется Melodic с Python 2 мостом, используйте заводские варианты из уроков 9.8–9.10. Укажите это в паспорте: переустановка ROS не нужна для файловых упражнений; отсутствие bridge не исправляется установкой случайных pip-пакетов.

Скачайте один результат на ноутбук и откройте его. Работайте в [личной копии курса](SETUP_ROBOT.md#0-подключитесь-и-создайте-личную-копию). Перед запуском камеры и master проверьте существующие процессы по инструкции настройки. Для обязательных заданий используйте сохранение файлов через SSH; графический сеанс нужен только выбранным GUI-примерам.

## 2. Распределите работу в группе

Оптимальная учебная группа — 2–3 студента. **Оператор** запускает команды и фиксирует среду; **экспериментатор** меняет один параметр или условие и сравнивает результаты; **автор отчёта** сохраняет исходники, метаданные и объяснение. При двух студентах экспериментатор также оформляет отчёт. Меняйте роли после каждой темы, чтобы каждый участник хотя бы один раз самостоятельно выполнил запуск.

В начале занятия повторите прошлый результат, затем прочитайте цель новой работы и выполните исходный пример. После этого измените один параметр, сравните наблюдения и заполните [отчёт](../templates/REPORT.md). Сохраните исходный файл, команду, результат и объяснение изменений: одного итогового скриншота недостаточно. При работе в одиночку выполните все три роли самостоятельно.

## 3. Последовательность 11 тем

| Тема | Что выполняют самостоятельно | Условие завершения аппаратной части |
|---|---|---|
| 9.1. Первое изображение | BGR, серое изображение, свойства кадра | Достаточно файла; затем полезно повторить со своим кадром |
| 9.2. Геометрия | Размер, обрезка, поворот, перспектива | Достаточно файла с объяснёнными размерами |
| 9.3. Рисование и маски | Аннотация, маска, контуры | Достаточно файла; сохранить параметры и исходник |
| 9.4. Улучшение | Сравнение фильтров и яркости | Достаточно контролируемого опыта на одном исходнике |
| 9.5. Приложения | QR/объекты; дополнительные готовые модели по инструкции | Для реального опыта нужен свой кадр; внешние модели загружаются заранее |
| 9.6. AR | Синтетическая накладка, печатный шаблон, калибровка | Для метрической позы нужны реальные снимки своей камеры, размер клетки и K/D |
| 9.7. ALVAR | Подготовительная геометрия и заводское обнаружение | Нужны настоящий ALVAR-маркер, калибровка и сообщение с подтверждённым ID |
| 9.8. Изображения ROS | Получение RGB/depth и метаданных | Нужен действующий поток; Python-мост либо выбранная заводская ветка |
| 9.9. Обработка ROS | Поток маски или опыты `opencv_apps` | Нужны реальные входной/выходной топики и результат обработки |
| 9.10. Пространственные данные | Синтетический скан, PCD, преобразование | Для опыта на стенде нужен реальный LaserScan/PointCloud2 и известный frame |
| 9.11. MediaPipe | Кисть, поза, лицо и влияние условий | Нужны настоящие изображения и совместимая модель; выполнение допустимо на ноутбуке |

Перед темами 9.7–9.10 самостоятельно проверьте импорт ROS-модулей, связь с master, тип и частоту входного топика. Зафиксируйте способ остановки: Ctrl+C для своего launch или встроенный предел времени учебного скрипта. Сохранение кадра из 9.8 можно выполнить заранее для калибровки в 9.6. Темы MediaPipe также можно проводить на ноутбуке по кадрам, полученным на ROSMASTER.

В [таблице прогресса](../templates/PROGRESS.md) отдельно отмечайте «подготовительная практика выполнена» и «проверено на реальных данных/стенде». Успешный синтетический пример не подтверждает испытание робота. Отсутствие оборудования не мешает выполнить подготовительную часть; аппаратный статус остаётся открытым до настоящего опыта.

## 4. Самопроверка — 12 баллов

Эта шкала предназначена для учебной обратной связи по одной работе. **Она не изменяет утверждённый силлабус, недельное распределение баллов, СРС или правила итогового контроля.** Перенос результата в университетскую систему выполняется по действующему силлабусу.

| Критерий | Максимум | Начисление: по 1 баллу за каждое выполненное условие |
|---|---:|---|
| Результат | 4 | Самостоятельно повторён запуск; получен ожидаемый артефакт; сохранён исходник; происхождение данных и фактическая среда указаны корректно |
| Эксперимент | 3 | Изменён понятный параметр/условие; сохранены сравниваемые результаты; сформулирован вывод, опирающийся на наблюдение |
| Объяснение | 3 | Объяснён основной алгоритм; правильно названы координаты/единицы/кодировки, где применимо; объяснена одна ошибка или граница метода |
| Отчёт | 2 | Команда и параметры позволяют повторить работу; файлы и ответы оформлены по шаблону |
| **Итого** | **12** | Оценивается фактически выполненная и заявленная часть |

Офлайн-упражнение может получить полный балл по своей заявленной цели, сохраняя отдельную отметку о ещё не выполненной аппаратной части. Нулевое обнаружение модели допустимо как наблюдение, если исходник сохранён, причина исследована и результат описан честно.

## 5. Проверка перед опытом на оборудовании

- Платформа устойчиво размещена, питание и зарядка соответствуют инструкции установленного оборудования.
- Название камеры, рабочий драйвер и место запуска совпадают с паспортом; устройство открывает один процесс, его PID и команда проверены.
- RGB-кадр действительно поступает, достаточно резкий и имеет записанное разрешение.
- Для depth/LiDAR/облака известны тип сообщения, frame и принятые единицы; неизвестная внешняя калибровка не подставлена произвольно.
- Используются ограниченные по времени учебные программы; оператор знает, как завершить заводской launch через Ctrl+C.
- Результаты пишутся в отдельную папку группы; свободного места достаточно для выбранной короткой записи.
- После опыта сохранены исходные данные, параметры, результат и комментарий об ограничениях; собственные окна/процессы закрыты.

В этом курсе работа с платформой состоит в получении и обработке данных. Для выполнения перечисленных проверок команды движения и управление приводами не нужны.
