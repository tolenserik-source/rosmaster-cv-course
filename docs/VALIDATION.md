## Проверенная среда

Linux x86_64, Python 3.12.14, NumPy 1.26.4, OpenCV 4.11.0.86 (`opencv-contrib-python-headless`). Зависимости установлены из `requirements-qa.txt` в отдельное временное виртуальное окружение. Это среда проверки учебного кода; её скорость не характеризует робот.

Unit tests проверяют реальные свойства данных и математики: каналы, типы и размеры, пороги красного цвета, геометрическое преобразование, восстановление известной искусственной позы, обработку недопустимых лучей, ASCII PCD, жёсткое преобразование координат и сохранение исходных значений depth/NaN. Отдельный тест проверяет завершение зависшего ROS-задания с пределом времени, который охватывает инициализацию.

Синтаксическая проверка по грамматике Python 3.6 пройдена для основных модулей и блокнотных ячеек. Она не заменяет запуск на старом ARM-образе с его бинарными зависимостями. Для ROS-программ требуется отдельная проверка доступности Python bridge в установленной среде.

## Что не подтверждено этой сборкой

- Физическая камера, ROS master и фактические топики вашего ROSMASTER.
- Реальная калибровка камеры и метрическая точность AR.
- Настоящее распознавание ALVAR и корректность размера напечатанного маркера.
- Реальные единицы depth, frame_id, LiDAR и PointCloud2.
- Совместимость нейросетевых библиотек с конкретной ARM-платой.
- Инференс SSD/OpenPose с внешними весами и качество распознавания MediaPipe на людях.

В подготовке до восстановления рабочей среды выполнялись загрузка и обработка одного синтетического PNG официальными MediaPipe Hand/Pose/FaceLandmarker на CPU. Людей на картинке не было, получено 0 обнаружений. Этот опыт подтверждал загрузку моделей и вызов API, но не распознавание человека и не совместимость с роботом; в критерий аппаратного зачёта он не включается.

Для закрытия аппаратных пунктов преподаватель проходит [паспорт стенда](../templates/ROBOT_PASSPORT.md) и [инструкцию настройки](SETUP_ROBOT.md). Студент отмечает подготовительный и реальный опыт отдельно в [листе прогресса](../templates/PROGRESS.md).

## Как повторить программную проверку

Создайте новое окружение на ноутбуке с Python 3.9–3.12. Из корня курса, Linux/macOS:

```bash
python3 -m venv .venv-qa
source .venv-qa/bin/activate
python -m pip install -r requirements-qa.txt
python -m unittest discover -s tests -v
python tools/final_project.py --source data/demo.avi --max-frames 60 --out outputs/final_check
```

Для Windows можно вызывать `.venv-qa\Scripts\python.exe` напрямую. Не устанавливайте QA-зависимости поверх заводского OpenCV робота.

Пересборка блокнотов:

```bash
python tools/build_notebooks.py --strict
```

Пересборка автономной HTML-книги требует установленного Pandoc; чтение готового HTML дополнительных программ не требует:

```bash
python tools/build_handbook.py --strict
```

Число кадров, обнаружений и FPS не являются общей точностью детектора. Для итогового проекта используется собственная ручная проверка контрольных кадров по [заданию](FINAL_PROJECT.md).
