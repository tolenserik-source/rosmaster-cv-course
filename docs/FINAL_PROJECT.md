# Итоговый проект: визуальный инспектор красных объектов

**Задача:** создать воспроизводимую программу, которая получает изображение или последовательность кадров, выделяет красные объекты, подписывает их и сохраняет измерения. Робот во время съёмки неподвижен. Результат проекта — работающая обработка, собственный эксперимент и объяснение ошибок метода.

## Что вы уже знаете

Уроки 9.1–9.5 дают чтение кадров, BGR/HSV, пороговую маску, морфологию, контуры и подписи. Уроки 9.8–9.9 показывают, как получить изображение через ROS. Итоговый проект соединяет эти шаги. На первом запуске используйте комплектное видео, затем настоящие кадры.

## 1. Получите базовый результат

Из корня репозитория в нужном Python-окружении:

```bash
python3 tools/final_project.py --source data/demo.avi --max-frames 60 --out outputs/final_baseline
```

Откройте `summary.json`, `measurements.csv`, `annotated_0001.png` и `mask_0001.png`. Программа также сохраняет изображения каждого десятого кадра. В CSV одна строка на кадр: номер, количество объектов, число пикселей маски и время обработки. В JSON собраны параметры и итоговая статистика.

`objects` — количество подходящих контуров в кадре. Оно не является глобальным ID, трекингом одного предмета или точностью распознавания. Площадь контура и число пикселей маски тоже могут различаться: это разные способы измерения области.

## 2. Проверьте собственную сцену

Возьмите красный предмет, например крышку или лист бумаги. Поместите его на однотонный фон. Получите фото или подтверждённый видеопоток по [инструкции настройки](SETUP_ROBOT.md).

Для файла:

```bash
python3 tools/final_project.py --input student_photos/red_object.jpg --out outputs/final_own
```

Для камеры самостоятельно определите устройство по [инструкции](SETUP_ROBOT.md#4-проверьте-настоящую-камеру) и впишите его в паспорт. Индекс 0 ниже — пример; замените его своим проверенным путём, например `/dev/camera_usb` на host нашего стенда, если устройство свободно:

```bash
python3 tools/final_project.py --source 0 --max-frames 60 --out outputs/final_camera
```

Если устройство открыто ROS-драйвером, получите кадр через урок 9.8 и передайте сохранённый PNG через `--input`, либо используйте маску узла 9.9. Не открывайте ту же камеру вторым процессом.

## 3. Проведите три контролируемых опыта

Подготовьте три условия: светлый ровный фон; изменённое освещение; фон с посторонним красным элементом. В каждом сохраните десять контрольных кадров. Изменяйте только одно условие за опыт, иначе причину разницы будет трудно объяснить.

Для каждого набора сравните исходные параметры и один новый порог, например:

```bash
python3 tools/final_project.py --source data/demo.avi --max-frames 60 --min-area 800 --saturation-min 120 --out outputs/final_changed
```

На собственных данных замените `--source` своим файлом/камерой. Сначала меняйте один параметр: `--min-area` отсекает маленькие контуры, `--saturation-min` задаёт минимальную насыщенность. Для чистого сравнения двух настроек используйте одно сохранённое видео, а не две разные съёмки.

## 4. Оцените результат вручную

Для простой и однозначной проверки в контрольной серии используйте один целевой красный предмет. Для каждого из десяти кадров отметьте, есть ли он, и нашла ли программа соответствующий ему контур. Посторонний красный объект считается ложным обнаружением относительно вашей задачи, даже если цвет определён правильно.

| Условие | Настройки | Контрольных кадров | Предмет правильно найден | Предмет пропущен | Ложные контуры |
|---|---|---|---|---|---|
| Ровный фон | Базовые | 10 | | | |
| Ровный фон | Изменённые | 10 | | | |
| Другое освещение | Базовые | 10 | | | |
| Другое освещение | Изменённые | 10 | | | |
| Сложный фон | Базовые | 10 | | | |
| Сложный фон | Изменённые | 10 | | | |

Явно опишите, как вы сопоставляли контур целевому предмету. Можно дополнительно вычислить долю кадров, на которых предмет найден, среди кадров с предметом. Не называйте её общей точностью по всем объектам и условиям. Для нескольких объектов уже нужна отдельная разметка и правило сопоставления каждого обнаружения.

Время в `summary.json` относится к вашему компьютеру и конкретному запуску. Чтение файла быстрее его частоты записи не означает, что камера выдаёт такой FPS. Не сравнивайте производительность роботов по числу кадров из разных сред.

## 5. Что сдать

- Исходные собственные кадры/видео и точные команды запуска.
- PNG с масками и аннотациями, CSV/JSON обоих вариантов.
- Заполненную таблицу трёх условий.
- Короткое объяснение BGR → HSV → два диапазона красного → морфология → контуры → фильтр площади → подпись.
- Вывод: когда метод пригоден, почему он не понимает смысл предмета и какой один следующий шаг вы предложили бы.

Оформление: [шаблон отчёта](../templates/REPORT.md). Для защиты достаточно 3–5 минут демонстрации: запустите программу заново, измените один параметр и объясните наблюдаемое изменение. Проверьте работу по [критериям самопроверки](TEACHER.md).
